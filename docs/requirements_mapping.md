# Official Requirements to Architectural Components Mapping

This document provides a 1-to-1 traceability matrix between the FarmwiseAI Campus Product Challenge problem requirements and the AgriMind implementation architecture.

| Requirement ID & Description | AgriMind Architectural Component | Primary Code Modules | Implementation Details |
|:---|:---|:---|:---|
| **REQ-1**: Accept text, documents, images, and structured data | Multimodal Input Ingestion Pipeline | `backend/app/processing/`, `backend/app/schemas/request.py`, `backend/app/api/` | Handles text queries, PDF files (PyMuPDF/OCR), images (Pillow/OpenCV), and CSV/JSON parcel files with size limits and SHA256 checksums. |
| **REQ-2**: Interpret request, constraints, outputs, and missing info | Request Understanding & Intent Extraction Node | `backend/app/agents/nodes/request_understanding.py` | Extracts explicit constraints, identifies missing parameters (e.g. location for weather, crop species), and formats structured user context. |
| **REQ-3**: Create explicit execution plan with meaningful steps | Dynamic Planner Node | `backend/app/agents/nodes/planning.py`, `backend/app/schemas/plan.py` | Generates a validated `ExecutionPlan` containing discrete `PlanStep` items with explicit dependencies (DAG) and task classifications. |
| **REQ-4**: Route each step to appropriate AI model or tool | Capability-Aware Router | `backend/app/routing/router.py`, `backend/app/schemas/routing.py` | Evaluates task type, modality requirements, availability, latency, and cost to assign the best model or tool with an explicit logged rationale. |
| **REQ-5**: Use at least 2 commercial/proprietary models and 1 open-weight/smaller model | Multi-Provider Model Registry | `backend/app/models/registry.py`, `backend/app/models/adapters/` | - Commercial 1: Google Gemini 1.5 Flash (Vision & Multimodal)<br>- Commercial 2: Groq Llama 3.3 70B (High-throughput reasoning)<br>- Open-Weight: Ollama Llama 3.2 3B (Local/edge tasks). |
| **REQ-6**: Select models based on task type, capability, confidence, latency, cost | Heuristic Routing Engine | `backend/app/routing/heuristic.py` | Transparent scoring function weighing capability match, measured latency, estimated token cost, and past reliability metrics. |
| **REQ-7**: Call at least two meaningful tools or data sources | External Tool Connectors | `backend/app/tools/weather.py`, `backend/app/tools/knowledge.py`, `backend/app/tools/structured_data.py` | - Tool A: Open-Meteo Weather Connector (live forecast/historical weather)<br>- Tool B: FAISS Agricultural Advisory Retriever (grounded PDF knowledge)<br>- Tool C: Structured CSV/JSON parcel/soil data query tool. |
| **REQ-8**: Produce validated structured outputs | Pydantic Schema Enforcement | `backend/app/schemas/`, `backend/app/verification/schema_validator.py` | All inter-node messages, tool results, and final responses are strictly validated through Pydantic V2 schemas with custom validators. |
| **REQ-9**: Maintain shared execution state and intermediate results | LangGraph Workflow State | `backend/app/agents/state.py` | Strongly-typed `AgriMindState` object passed across all nodes, holding inputs, execution plan, intermediate outputs, evidence, and traces. |
| **REQ-10**: Verify important facts, calculations, and model outputs | Verification & Critic Stage | `backend/app/verification/critic.py`, `backend/app/schemas/verification.py` | Performs deterministic Python calculations (soil nutrient math, thermal indices), verifies citation grounding, and checks for contradictions. |
| **REQ-11**: Preserve source references for important results | Evidence Tracking & Citation Engine | `backend/app/retrieval/`, `backend/app/schemas/tools.py`, `backend/app/schemas/response.py` | Records document names, page/section pointers, and tool timestamps as `RetrievedEvidence` and embeds them into `FinalResponse.source_references`. |
| **REQ-12**: Recover when models, APIs, tools, or data sources fail | Fault Recovery Controller | `backend/app/agents/nodes/recovery.py`, `backend/app/schemas/trace.py` | Configurable recovery paths: bounded exponential backoff retries, transparent switching to pre-assigned fallback models, and partial results with limitations. |
| **REQ-13**: Track model selection, routing decisions, latency, cost, fallbacks | Execution Tracing & Telemetry | `backend/app/database/`, `backend/app/schemas/trace.py` | SQLite database storing every model call, prompt/completion token count, estimated USD cost, millisecond latency, and fallback event. |
| **REQ-14**: Produce useful final result for the agricultural use case | Agricultural Synthesizer Node | `backend/app/agents/nodes/synthesizer.py`, `backend/app/schemas/response.py` | Generates a final response categorizing observed symptoms, weather context, retrieved advisory evidence, possible causes, and actionable recommendations. |
| **REQ-15**: Demonstrate on a comparable, previously unseen request | Benchmark Evaluation Suite | `data/evaluation/`, `scripts/run_evaluations.py` | Validates the system against test queries (e.g. Pest outbreak vs Fertilizer burn vs Drought stress) comparing baseline vs proposed multi-model pipeline. |
